# 완료 기준과 증거

## Phase 1 종료

- 서로 다른 지점을 두드렸을 때 각 위치에 별개의 손상이 남고, 반복 타격은 해당 부분의 깊이를 바꾼다.
- 0/25/50/75/100% 시각 증거에서 표본이 암석층 아래에서 점진적으로 드러난다.
- 연속 입력에서 파편과 먼지가 누락되거나 무한 누적되지 않는다. resize/회전 후 입력 위치가 어긋나지 않는다.
- 90%에서 브러시 마무리 단계로 전환하며 브러시로 먼지를 골고루 제거해야만 성공한다. 망치를 계속 사용해 100%에 도달하면 암석/표본이 파손되고 도감에 등록되지 않는다. 성공/파손 후 입력은 상태를 바꾸지 않으며 재시작이 이전 손상·오디오를 정리한다.
- 도감은 50칸 격자를 한 화면 흐름에서 탐색할 수 있어야 한다. 미발견은 `???`로 표시하고 실제 획득한 종만 이미지·이름·등급·횟수를 공개한다. 50종 모두 개별 이미지가 있고 실제 추첨·발굴·기록이 가능해야 한다. 미구현을 완성품으로 숨기지 않는다.
- 브라우저에서 사용자 첫 입력으로 소리가 활성화되고 mute/볼륨이 반영된다. 실제 청취 여부를 기록한다.
- 임시 합성음·미완성 표본·미확보 라이선스를 명시한다.

## 테스트 배분

| 검증 | 관찰할 동작 |
| --- | --- |
| 순수 로직 | RNG 경계·등급 내 균등성·손상 국소성·완료 기록 멱등성·저장 migration/실패 |
| 브라우저 | 좌표 변환·도구 전환·pointercancel·회전·재시작·설정 유지·접근성 |
| 시각 검토 | 모바일 4개 폭·단계별 암석 제거·조명 일관성·글자 넘침·안전 영역 |
| 오디오 | 실제 청취·변주·연타 시 피크·mute·첫 입력·백그라운드 복귀 |
| 실기기 | iOS/Android 토스 WebView 오디오·입력·메모리·성능·저장 유지 |
| 출시 | 공식 빌드 성공·AIT 파일 생성·콘솔 업로드/컴파일·심사 결과를 각각 기록 |

처음부터 불필요한 테스트를 대량 작성하지 않는다. 핵심 상태와 입출력 불변 조건에 테스트를 집중한다. Playwright CLI 스킬은 수동 자동화·증거 캡처에 사용하며 테스트 프레임워크 도입은 별도 필요가 생길 때 결정한다.

## 증거 규칙

스크린샷/추적은 `app/output/playwright/`, 측정 보고서는 `harness/evidence/`에 둔다. 파일에는 단계·뷰포트·날짜를 식별할 수 있는 이름을 쓴다. 성능 보고에는 기기·OS·WebView·테스트 길이·DPR·입자 수·프레임 지연 분포·메모리 변화·비교 전후를 남긴다.

실행하지 않은 검사는 `미검증`, 실패는 `실패`, 통과는 명령/관찰 근거와 함께 `통과`로 기록한다. 빌드 성공은 청취·실기기·콘솔 심사 통과를 대체하지 않는다.
