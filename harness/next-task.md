# 다음 작업 — 50종 체험의 출시 품질 검증

`AGENTS.md`, `harness/status.md`, `harness/evidence/phase-1-browser.md`를 먼저 읽는다. 이미 만들어진 `app/`을 사용하고 다시 scaffold하지 않는다. 기존 짐싸줘 소스는 변경하지 않는다.

1. 사용자에게 현재 미리보기의 타격음·손맛 피드백이 있으면 반영한다. 합성음을 실제 녹음 ASMR과 동등하다고 주장하지 않는다.
2. 상업 이용·재배포 조건을 검증할 수 있는 실제 돌/균열/브러시 녹음 샘플을 조사하고 원문 라이선스·출처·표시 의무를 기록한 뒤 통합한다. 확인되지 않은 음원을 다운로드해 사용하지 않는다.
3. 실제 콘솔 appName을 확인하고 iOS/Android 토스 WebView 테스트를 진행한다. SDK 저장 어댑터, 첫 제스처 오디오, 앱 복귀, 터치 좌표, 메모리와 장시간 프레임 지연을 검증한다. 업로드/심사 등 외부 변경은 해당 작업의 실제 승인 범위에 맞춰 진행한다.
4. 생성 표본의 형태와 설명을 과학적으로 검토한다. 인증된 사진처럼 표기하지 않는다. 원본과 프롬프트를 보존하고 모바일 배포 용량을 관리한다.
5. 50종을 임시 카드로 대체하거나 기존 발견 기록을 초기화하지 않는다. `check_harness.py --strict-catalog`와 `node scripts/audit-specimens.mjs`로 데이터·이미지 무결성을 유지한다. 광고 도입 시 별도 정책·연동·실기기 검증을 한다.

수정마다 필요한 검사만 다시 실행하고 `harness/status.md`와 증거를 갱신한다. 완료 판정은 브라우저·청취·실기기·콘솔을 구분한다.
