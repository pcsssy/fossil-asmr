# 구현 기준

## 개발 기반

후속 구현에서 `app/`을 공식 create-ait-app으로 생성하고 React + TypeScript + Vite + 공식 SDK 조합을 확인한다. 현재 설치된 Node는 v24.22.0이다. 부모 앱의 node_modules와 SDK 3.8.0을 새 앱의 검증된 버전으로 간주하지 않는다.

첫 엔진 후보는 Canvas 2D다. 지역 마스크 합성·파편 수·텍스처 크기를 프로토타입에서 측정하고 부족하면 PixiJS/WebGL을 비교한다. 엔진 변경은 측정 근거와 텍스처 메모리 비용을 남긴다.

## 계층 경계

- `engine`: 입력 좌표 변환, 다층 손상 필드, 균열, 파편 풀, 먼지, 렌더 루프. React에 의존하지 않는 상태와 시간 단위 사용.
- `audio`: 사용자 제스처 unlock, 미리 디코딩한 샘플, voice 제한, 변주, gain/fade, visibility 정리.
- `domain`: 카탈로그, 등급 확률, 회차 상태, 완료 판정, 중복 등록. RNG를 주입해 재현 가능하게 한다.
- `platform`: 저장·진동·광고·SDK 브리지. 브라우저 개발 어댑터와 실제 WebView 구현을 구분한다.
- `ui`: 홈·도감·설정·접근성. 고빈도 위치/입자 상태를 React state로 전달하지 않는다.

## 지역 파괴

입력은 CSS 좌표를 캔버스 논리 좌표로 변환하며 DPR·resize·회전에 대응한다. pointer capture와 pointercancel을 처리하고 작업 캔버스에서만 스크롤을 제한한다.

손상 필드/마스크에 지점별 깊이를 저장한다. 4–6층을 후보로 하되 메모리를 측정한다. 재렌더 후에도 손상 위치가 유지되어야 한다. 전체 이미지 opacity나 탭 횟수만으로 진행시키지 않는다. 브러시는 경로를 따라 표면 잔여물을 제거한다.

완료는 목표 표본 영역의 노출 상태로 판정하고 20–40회는 초기 튜닝 범위로만 쓴다. 동일 지점 반복 입력만으로 원거리 암석이 설명 없이 사라지지 않도록 설계한다. 마지막 정리 연출은 충분한 실질 노출 후 사용한다.

2026-10-24 사용자 변경: 노출률 90%는 완료가 아니라 `brushing` 단계의 시작이다. 해당 단계에서는 별도 지역 먼지 필드를 브러시로 90% 이상 정리해야 `completed`가 된다. 망치를 계속 사용하면 표시 진행률이 한 번당 2.5%p씩 올라가고 100%에서 `broken`이 된다. 먼지를 덜 털었는데 망치로 성공 처리하지 않는다. 파손 회차에는 도감 등록 콜백을 호출하지 않는다. 성공과 파손은 모두 종결 상태이며 재시작으로만 새 회차가 된다.

## 오디오

타격·균열·잔해·브러시·공개를 레이어로 분리한다. 제스처 안에서 AudioContext.resume을 호출하고, 이후 입력은 준비된 샘플을 즉시 재생한다. 서버 요청/새 decode 완료를 매 타격마다 기다리지 않는다.

최근 샘플 반복 방지와 작은 pitch/gain 변화, 동시 발음 제한, master gain, 짧은 fade를 둔다. 장시간 백그라운드 전환/복귀 및 mute를 테스트한다. 실제 녹음이 없으면 임시 합성음으로 표시한다. 녹음 샘플은 라이선스 검증 후 통합한다.

## 저장과 성능

정의 데이터와 사용자 기록을 분리하고 저장 포맷에 버전을 둔다. 손상 데이터·중복 탭·재진입에도 발굴 완료 기록이 한 번만 추가되어야 한다. 저장 실패 시 성공으로 표시하지 않는다.

화면 이탈 시 rAF, 이벤트 리스너, audio voice를 정리한다. 텍스처 재사용·파편 풀·DPR 상한·저품질 프리셋을 제공할 수 있게 한다. 목표는 지원 기기에서 60FPS에 가깝게 유지하는 것이며, 측정 전 성능 달성을 주장하지 않는다.
