# 앱인토스 미니앱 개발 프로젝트 — 화석발굴 ASMR

당신은 15년 이상 경력의 모바일 앱 개발자, 게임 인터랙션 엔지니어, 사운드 디자이너, UI/UX 디자이너다.

이번 프로젝트는 앱인토스(Apps in Toss)에 출시할 고품질 인터랙티브 ASMR 발굴 체험 앱이다.

단순한 클릭형 웹페이지나 정적인 이미지 기반 앱이 아니라, 사용자가 화면을 두드릴 때마다 암석이 깨지고 파편이 흩어지며 내부에 숨겨진 화석과 보석이 드러나는 실제 체험형 애플리케이션을 개발한다.

## 1. 프로젝트 기본 정보

- 앱 이름: 화석발굴
- 영문 가칭: Fossil ASMR
- 서비스 콘셉트: 톡톡 두드리면 드러나는 신비로운 화석과 보석
- 플랫폼: Apps in Toss
- 핵심 장르: 인터랙티브 ASMR·발굴 체험·도감 콘텐츠
- 대상: 모바일 사용자
- 수익 모델: 앱인토스 광고, 향후 승인된 프로모션 연계

앱인토스 공식 문서:
https://developers-apps-in-toss.toss.im/

현재 프로젝트가 비어 있다면 공식 `create-ait-app` 도구를 사용하여 프로젝트를 구성한다.

앱인토스 콘솔에서 등록한 실제 appName이 제공되기 전까지는 임의의 최종 ID를 확정하지 않는다. 환경 설정에서 변경 가능하도록 만든다.

## 2. 최우선 개발 원칙

이 앱의 핵심 경쟁력은 ASMR과 시청각적 타격감이다.

다음과 같은 저품질 구현은 절대 최종 결과물로 인정하지 않는다.

- 돌 이미지를 클릭할 때마다 숫자만 증가하는 구현
- 클릭 횟수에 따라 이미지만 교체하는 단순한 구현
- 원이나 사각형으로 표현한 단순한 돌
- 이모지로 표현한 화석
- 실제 파괴 효과가 없는 균열
- 항상 동일한 기계적인 타격음
- 임시 이미지나 무음 애니메이션만으로 완성 처리

최종 목표는 '키캡 ASMR', '왁뿌볼', 물체 파괴 ASMR 콘텐츠처럼 사용자가 계속 터치하고 싶어지는 수준이다.

**핵심 품질 목표:**

1. 첫 화면부터 시각적으로 매력적일 것.
2. 터치 즉시 소리와 시각적 반응이 발생할 것.
3. 타격 지점이 실제로 손상되는 느낌일 것.
4. 암석이 점진적으로 제거될 것.
5. 내부 발굴물이 자연스럽게 노출될 것.
6. 화석과 보석마다 서로 다른 질감이 표현될 것.
7. 발굴 완료 후 시각적으로 만족스러운 연출을 보여줄 것.
8. 반복해서 사용해도 소리가 단조롭지 않을 것.
9. 모바일 기기에서도 부드럽게 실행될 것.

## 3. 기술 스택

- React
- TypeScript
- Vite
- Apps in Toss 공식 SDK
- Canvas 2D 또는 PixiJS
- 필요할 경우 WebGL 및 고품질 파티클 엔진
- Web Audio API 및 오디오 샘플
- 모바일 터치 이벤트 기반 인터랙션
- 로컬 저장 및 추후 서버 연동 가능한 데이터 구조

렌더링 엔진은 모바일 WebView 성능과 고품질 파괴 효과를 기준으로 선택한다.

PixiJS 사용 시 현재 공식 호환 버전을 확인한다.

화면 전체를 React DOM 애니메이션으로 구현하려 하지 말고, 고빈도 그래픽 효과는 Canvas/WebGL 렌더링 계층에서 처리한다.

앱의 메뉴와 도감 UI는 React 컴포넌트로 구성한다.

## 7. 랜덤 발굴 시스템

사용자가 발굴을 시작하면 50종 중 하나를 확률에 따라 선정한다.

등급 확률:
- 노멀 60%
- 레어 28%
- 스페셜 10%
- 전설 2%

발굴 결과는 시작 시점에 내부적으로 선정하되, 실제 발굴이 완료되기 전까지 사용자에게 노출하지 않는다.

일반적인 랜덤 선택 방식을 사용하며, 결과가 특정 광고 시청 여부에 따라 조작되거나 사용자에게 표시된 확률과 달라지지 않도록 한다.

등급 및 개별 아이템 확률을 앱 내에서 확인할 수 있도록 만든다.

중복 발굴을 허용하고 중복 발견 횟수를 도감에 기록한다.

50종 수집률을 계산한다.

## 8. 핵심 발굴 인터랙션

앱의 가장 중요한 부분이다.

사용자는 암석 중앙을 두드려 내부의 발굴물을 찾아낸다.

### 8-1. 타격 시스템

사용자 터치 위치를 감지한다.

터치하면:
1. 망치 타격 모션
2. 충격 지점에 짧은 흔들림
3. 표면에 미세한 균열
4. 작은 암석 파편 생성
5. 먼지 입자 발생
6. 암석 타격 ASMR
7. 해당 위치의 암석 일부 제거

모든 시각 효과는 터치 위치를 기준으로 발생한다.

손가락을 빠르게 반복 터치해도 자연스럽게 반응해야 한다.

### 8-2. 암석 파괴 시스템

단순히 이미지 투명도를 일정 비율로 감소시키는 방식만 사용하지 않는다.

실제 파괴된 위치가 남아 있도록 한다.

추천 기술:
- 다층 암석 이미지
- 지역 기반 손상 마스크
- 균열 패턴
- 파편 파티클
- 먼지 입자
- 암석 내부 깊이 표현
- 단계별 손상 텍스처
- 불규칙한 암석 가장자리

암석은 4~6개 층으로 구성할 수 있다.

외부 암석층이 제거될수록 내부 화석이 드러난다.

발굴물의 형태에 따라 손상 마스크가 자연스럽게 작동하도록 한다.

### 8-3. 발굴 진행

예시:

초기:
암석이 완전히 덮여 있다.

초반:
미세한 금과 작은 파편 발생.

중반:
돌 조각이 떨어지고 내부 지층이 드러남.

후반:
화석의 일부 형태가 보이기 시작함.

완료 직전:
넓은 암석층이 제거되면서 발굴물이 거의 노출됨.

완료:
남은 파편이 자연스럽게 떨어지고 발굴물이 완전히 나타남.

매 타격이 똑같은 애니메이션이 되지 않도록 약간의 랜덤성을 적용한다.

대략 20~40회의 타격으로 하나의 발굴을 완료할 수 있도록 기본 설정한다.

단, 실제 테스트를 통해 손맛과 피로도를 고려해 조정한다.

## 9. 발굴 도구

기본 도구는 두 가지다.

### 망치
- 탭으로 타격
- 암석에 균열 발생
- 파편 제거
- 짧고 묵직한 사운드

### 브러시
- 손가락 드래그
- 먼지와 모래를 제거
- 작은 입자들이 이동
- 부드러운 브러싱 ASMR

도구 변경은 발굴 화면 하단에서 한 번의 터치로 가능하게 한다.

망치와 브러시 모두 실제 터치 위치에서 작동해야 한다.

초반에는 망치만으로도 발굴 완료가 가능하게 하고, 브러시는 사용자가 더 섬세하게 감상하도록 돕는 보조 기능으로 설계한다.

## 10. ASMR 오디오 시스템

이 앱에서 사운드는 핵심 기능이다.

반드시 실제로 들을 수 있는 사운드를 구현한다.

필요한 효과음:

1. 약한 암석 타격음
2. 강한 암석 타격음
3. 미세한 균열음
4. 돌 조각 떨어지는 소리
5. 돌이 갈라지는 소리
6. 모래 쓸리는 소리
7. 브러시 먼지 제거음
8. 작은 자갈 움직이는 소리
9. 화석 노출 시 가벼운 효과음
10. 발굴 완료 사운드
11. 스페셜 등장 사운드
12. 전설 등장 사운드
13. 보석 결정체가 드러나는 맑은 소리

### 오디오 구현 기준

가능하면 라이선스가 명확한 고품질 실제 녹음 음원을 사용한다.

상업 이용이 가능한 무료 음원을 우선 조사하고, 저작자 표시 의무가 있는 경우 이를 준수한다.

다운로드 가능한 음원이 없으면 Web Audio API를 활용하여 임시 프로시저럴 사운드를 구현한다.

단, 합성음은 임시 음원임을 명시하고 실제 ASMR 녹음 음원과 동등한 품질이라고 주장하지 않는다.

확인되지 않은 음원을 임의로 사용하지 않는다.

오디오 요구사항:
- 짧은 응답 지연
- 터치와 소리 동기화
- 여러 음원의 자연스러운 레이어링
- 매 타격마다 약간씩 다른 음량과 피치
- 같은 음원 무한 반복에 따른 피로감 방지
- 부드러운 페이드 처리
- 과도한 피크 및 음량 방지
- 모바일 WebView 사용자 제스처 기반 오디오 활성화
- 사운드 ON/OFF
- 효과음 볼륨 조절
- 무음 상태에서도 시각적 체험 가능

사운드 파일과 관련 라이선스 정보는 별도 폴더와 문서로 관리한다.

타격할 때마다 실제로 소리가 재생되는지 브라우저와 모바일 환경에서 테스트한다.

## 12. 발굴물 그래픽 에셋

50종 모두 시각적으로 구별되는 고유 에셋을 갖도록 설계한다.

이모지, 텍스트, 기본 도형을 최종 발굴물 이미지로 사용하지 않는다.

가능하면 실물 표본이나 실제 광물 형태를 기반으로 고품질 에셋을 확보한다.

에셋 우선순위:
1. 상업 이용이 허용된 검증 가능한 이미지 또는 3D 에셋
2. 적법한 라이선스의 자체 가공 에셋
3. 생성형 이미지 도구로 제작한 고유 이미지
4. 초기 테스트용 임시 그래픽

외부 이미지의 라이선스를 확인하고 출처를 관리한다.

이미지 생성 도구가 현재 환경에서 지원되지 않으면, 없는 기능을 구현했다고 주장하지 않는다.

우선 대표 6종을 고품질로 구현한다.

대표 6종:
- 티라노사우루스 두개골
- 암모나이트
- 다이아몬드 원석
- 자수정
- 조개 화석
- 삼엽충

이 6종을 통해 서로 다른 재질과 발굴 연출을 검증한다.

이후 50종 전체에 확장한다.

대표 6종만 구현한 단계에서는 나머지 44종이 완성된 것처럼 사용자에게 노출하지 않는다.

## 15. 광고 수익화

최종적으로 앱인토스 공식 광고 SDK 사용을 고려한다.

광고 위치 후보:

1. 홈 화면 하단 배너
2. 도감 화면 하단 배너
3. 발굴 완료 후 자연스러운 전환 시점의 전면 광고

발굴 중에는 전면 광고를 노출하지 않는다.

타격 중 실수로 광고를 누르지 않도록 광고와 인터랙션 영역을 분리한다.

실제 광고 빈도와 위치는 앱인토스 정책과 SDK 지원 범위를 확인한 후 결정한다.

MVP에서는 광고 SDK 연동이 불가능할 경우 광고 관련 컴포넌트만 분리하고 실제 수익이 발생하는 것처럼 구현하지 않는다.

## 16. 토스 포인트 이벤트 확장

향후 토스에서 지원하는 공식 프로모션 기능을 통해 1~5원 상당의 이벤트를 진행하는 방안을 검토한다.

단, 초기 MVP에는 실제 현금성 보상을 지급하지 않는다.

발굴물 희귀도 및 랜덤 등장 확률과 현금성 보상 구조를 분리한다.

포인트 지급은 공식 지원 방식, 예산, 사용자 인증, 이벤트 횟수 제한, 부정 이용 방지, 정책 검토 이후에만 적용한다.

## 22. 최종 품질 기준

이번 프로젝트에서는 기능 개수보다 발굴 경험의 완성도가 우선이다.

발굴물 50종을 정적인 이미지로 보여주는 앱보다, 발굴물 6종이라도 실제로 돌이 깨지는 느낌을 제공하는 앱이 훨씬 가치 있다.

따라서 Phase 1과 Phase 2에서 시각 효과와 사운드 품질을 충분히 확보한 다음 나머지 콘텐츠를 확장한다.

디자인은 상업적으로 출시할 수 있을 정도의 수준을 목표로 한다.

플레이스홀더, 이모지, 단순 클릭 카운터로 최종 구현을 대체하지 않는다.

프로젝트에 코드 수정이 가능하다면 실제 구현까지 진행한다.

브라우저 또는 테스트 환경에서 검증 가능한 기능은 직접 테스트한다.

실제 실행 결과가 확인되지 않은 기능은 완료되었다고 보고하지 않는다.

완료 후 다음 정보를 정리한다.

1. 구현 완료 기능
2. 실제 적용된 그래픽 효과
3. 실제 적용된 사운드 및 라이선스
4. 완성된 발굴물 에셋 수
5. 미완성 또는 임시 구현 항목
6. 빌드 및 테스트 결과
7. 실행 방법
8. 앱인토스 출시 전 남은 작업

최종 목표는 **사용자가 계속 두드리고 싶어지는 고품질 '화석발굴 ASMR' 미니앱**을 개발하는 것이다.

지금 바로 프로젝트 구조와 개발 환경을 확인하고 Phase 1부터 실제 구현을 시작해줘.
